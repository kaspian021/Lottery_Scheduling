# گزارش فارسی — تمرین 3: حل دستی قرعه‌ها و جدول اجرای Lottery

## چکیده

محاسبهٔ دستی بازه‌های بلیت، برندهٔ قرعه، ترتیب اجرا و سهم مشاهده‌شده. این گزارش منطق الگوریتم، فرض‌های مدل و شواهد حاصل از اجرای کد را از ادعاهای عمومی جدا می‌کند.

## مسئله و هدف

در این تمرین، قرعه‌کشی به شکل جدولی قابل حل روی کاغذ ارائه می‌شود. با P1=5، P2=3 و P3=2 مجموع بلیت‌ها ده است. بازه‌های تجمعی P1 برابر ۱ تا ۵، P2 برابر ۶ تا ۸ و P3 برابر ۹ تا ۱۰ است. برای هر عدد قرعه، بازه‌ای که عدد در آن قرار می‌گیرد برنده را تعیین می‌کند.

برنامه ۱۵ قرعه با seed=7 تولید می‌کند و برای هر ردیف شماره تصمیم، عدد تصادفی، مجموع بلیت، برنده و بازهٔ برنده را ذخیره می‌کند. این جدول برای بررسی دستی مناسب است؛ برای بازتولید همان دنباله باید از همان seed و ترتیب پردازه‌ها استفاده کرد. تغییر seed یک دنبالهٔ دیگر اما معتبر تولید می‌کند.

سهم مشاهده‌شده تعداد بردها تقسیم بر تعداد قرعه‌هاست. این سهم تنها با افزایش تعداد قرعه‌ها به سهم نظری نزدیک‌تر می‌شود و برای نمونهٔ ۱۵تایی نوسان طبیعی است. جدول نباید به‌عنوان نتیجهٔ قطعی تخصیص CPU در هر اجرای واقعی تفسیر شود.

## مدل و روش اجرا

سناریوی این تمرین در `shared/experiments.py` تعریف شده و با تابع `run_exercise(3)` اجرا می‌شود. منبع دادهٔ گزارش، فایل `outputs/results.json` است. برای تکرار نتیجه، نسخهٔ کد و seed ثبت‌شده باید ثابت باشد.

## شبه‌کد Lottery

```text
while unfinished jobs exist:
    ready = jobs with arrival <= now and remaining > 0
    if ready is empty:
        advance time to next arrival
        continue
    T = sum(ticket[p] for p in ready)
    r = uniform_integer(1, T)
    winner = first job whose cumulative ticket interval contains r
    run winner for min(quantum, remaining[winner])
    update remaining time, first response and completion
```

## معیارهای ارزیابی

صحت ورودی‌ها، یکتایی شناسه‌ها، مثبت‌بودن ticket و burst، تکمیل همهٔ عملیات، سازگاری شمارنده‌ها، تکرارپذیری seed و صحت metricها بررسی می‌شود. زمان انتظار، پاسخ و turnaround از trace استخراج می‌شوند، نه از عددگذاری دستی.

## محدودیت‌ها

۱۵ قرعه برای نشان‌دادن روش محاسبه و بررسی دستی کافی است، اما برای نتیجه‌گیری آماری پایدار نمونهٔ کوچکی محسوب می‌شود. سهم مشاهده‌شده ممکن است با سهم نظری تفاوت داشته باشد. مدل گسسته نیز فرض می‌کند هر انتخاب یک quantum واحد مصرف می‌کند و هزینهٔ تعویض زمینه را صفر می‌گیرد. این نتایج به مدل آموزشی مربوط‌اند و ادعایی دربارهٔ تضمین زمان‌بندی در هستهٔ سیستم‌عامل ندارند.
